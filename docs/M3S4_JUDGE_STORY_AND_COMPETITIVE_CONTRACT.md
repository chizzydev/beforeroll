# BeforeRoll M3-S4 — Product story, sponsor leverage, and scored deliverables

## Problem-first demonstration

Tomorrow's film call sheet contains Scene 31 and Scene 32, both using unfamiliar dry-ice effects. A site agreement includes a general prerequisite for atmospheric vapor and a later signed, **scene-specific** variation granting a conditional exception ONLY to Scene 31. An additional sentence says Scene 32's extension remains unapproved.

Without Clocked, BeforeRoll can parse scene times, calculate overlaps, preserve original source ranges and show a visual shooting timeline; it cannot infer the general operational link between sublimating carbon dioxide and venue vapor conditions using these deterministic functions. The sponsor contribution must be observable: Clocked Decide separately evaluates candidate permit clauses against *each* natural-language scene row, identifies plausible restrictions and possible documentary grants, and leaves undecidable or untested cases explicitly unresolved. Nothing is automatically cleared.

The only honest zero-credit replay is Scene 31, which uses the user's **actual previously recorded M3-S2 four-clause response**. Scene 32 deliberately has **no prerecorded model answers**; it must show `NOT AI-EVALUATED`. The new cross-scene provider capability requires an owner-run live batch, not mocked test data.

## What the judge should see

1. Review Desk: two scene rows, visible model evidence status for each, source-backed timeline and controls.
2. Load the 2-scene offline replay. Scene 31 displays real recorded general prerequisite and signed conditional grant. Scene 32 remains unevaluated, proving the app does **not** invent results.
3. Live mode (if conducted and accepted): one controlled two-scene batch, each clause separately evaluated for each scene using Clocked Decide, 2×4 billable requests. Compare per-scene findings and click exact source citations. No manual clause picking required.
4. Modify permit or scene; stale model evidence is invalidated. Export a dossier that explicitly records model provenance, per-scene coverage, source quotes, uncertainty and the distinction between documentary grant and safety-prerequisite fulfillment.

## Scorecard-aligned work

- Practical value: distinguish scene-specific production risks and permission questions that a coordinator might miss; **real production usefulness remains unvalidated**.
- Core Clocked: live Decide inference connects unfamiliar natural-language activity with natural-language operational rules; owner-recorded scene 31 success is established, scene 32 still requires a fresh result.
- Additional endpoint breadth: Extract supports initial permit reading, but R7 shows extraction omissions. Fill and other endpoints are **not claimed** merely for breadth; only integrate a further endpoint if it materially improves correct scene/restriction discovery.
- Implementation/UX: two-scene timeline and model findings in actual desk, exact citations, per-scene status badges, bounded spending, fail-closed source updates, dossier.
- Documentation: README, quickstart, evidence limitations, tests, owner protocol and reproducible synthetic cases are part of implementation; final public demo and full write-up remain outstanding.

## Known threats / nonclaims

- Local segmentation is not comprehensive clause discovery. Short conditions may be excluded and must be reported; no negative model score proves global permission.
- Model probabilities are uncalibrated judgments; semantic matches can be wrong (e.g. ambiguous Scene 32 wording). Signed document authenticity and chronological precedence need human investigation.
- Initial evidence is synthetic, self-authored, tiny and selected. There is no independent professional evaluation, verified real permit data, established accuracy rate, or demonstrable improvement on production-specific held-out cases yet.
- This is at most a TWO-SCENE pilot; broad production compatibility, PDF intake, real data privacy/deployment and robust authority handling are still tracked.
- Owner's actual Clocked account was NOT contacted to build or test this increment; the complete new multi-scene API flow is so far mocked at transport level only.
