BEFOREROLL M3-S30 | INTERACTIVE EVALUATION | WINDOWS

1. Extract the entire ZIP into its own folder. Do not launch it inside the ZIP.
2. Have Node.js 20 or later installed (node.exe must be on PATH).
3. Double-click Start-BeforeRoll-Evaluation.cmd.
4. Your default browser opens automatically. No terminal commands, owner token,
   provider API key, payment account, or personal production documents required.
5. Explore the Archive Floor example (U01), which contains eight clearly
   attributed previously recorded Clocked answers. Select scenes and review
   evidence. The public-passage example (U02) starts with NO answers; click
   REPLAY U02 RECORDING to load its eight original recorded outputs locally.
6. In the Sources / Scope / Review / Changes / Evidence workflow, try the
   original sources, human reviews and source-change preview. All files are
   fictional and stored in a new temporary evaluation directory.
7. Click RESET EXAMPLES to discard the sandbox changes and restore the originals.
8. Close the launcher window to end the evaluation.

Optional one-click engineering regression: double-click
Verify-BeforeRoll-Windows.cmd. It runs the cumulative 479-test verification and
original Clocked preflight without contacting Clocked. No manual commands.

EVALUATION SCOPE AND ACCURACY
- All original permit and scene text is generated/fictional. There is no legal
  or filming clearance, and signatures and issuing authorities are not verified.
- The frozen U01/U02 answers were really recorded from Clocked Decide on these
  fictional scene/clause pairs during earlier experiments, NOT generated by a
  mock. The current production engine's request contract is DIFFERENT from the
  historical requests. The application labels this explicitly as a historical
  answer replay, not a current live model evaluation or current request receipt.
- No provider requests or billable actions occur in evaluation mode, including
  if machine environment variables contain a Clocked API key.
- Evaluation sandbox is loopback-only. It is not a public hosted multi-user
  deployment. Each launcher start creates a separate disposable sample store.
- Do not import your own real private documents in evaluation mode.
- Protected, local-owner production operation remains separate, unchanged,
  and requires its owner authentication as before.

Troubleshooting: If double-click fails, check Node.js 20+ is installed and
reopen Windows Explorer. The launcher prints a meaningful error and leaves
its window open for inspection if startup fails.
