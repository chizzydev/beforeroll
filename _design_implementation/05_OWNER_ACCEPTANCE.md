# One coordinated Windows owner acceptance

Allow about 25–35 minutes. This is one end-to-end review of the implemented application, not a new request to approve each engineering increment. All provided materials are fictional. No live Clocked request is needed.

## Open the production UI

From `C:\Users\HP\beforeroll-codex-phase1`, double-click **Start-BeforeRoll-Evaluation.cmd**. Use the localhost URL printed by that launcher. Keep its window open. It runs the redesigned actual application in credential-free evaluation mode, isolated from private production data.

The already running acceptance instance is also available at **http://127.0.0.1:3045/**. Port 3044 is the preserved design prototype; use 3045 or the normal launcher to judge production implementation.

1. On Overview, read the product purpose. Open Scenes. Confirm the activity, Clocked relationship, exact original passage and next human action are understandable. Inspect original provenance, then compare documentary scope for Scenes 47/48. Check AD-4 versus the unissued request. Return to Work.
2. Open Example controls and replay U02. Inspect the public-egress relationship, RP-7 for S62 and the request for S63. The origin must remain recorded/older request contract, with zero new calls.
3. Open the production picker. Create a new fictional production with a unique ID, such as `owner_design_20261026`, and a recognizable title. Confirm the truthful empty intake state.
4. From `_design_implementation\fixtures\`, import `permit-A.docx` with stable ID **BASE**, `variation.pdf` with stable ID **VARIATION**, and `scenes.csv` as a structured call sheet. Read the original PDF and verify its extracted text under your reviewer name and rationale. Confirm two scenes and eight planned checks, with no invented model result.
5. In Scenes, select S31 and BASE/U002. Record a named, reasoned review, then stage it. Confirm commitment is unavailable until verification. Verify and commit. Navigate History and confirm the real saved record. In Work→Dates & conditions, add a dated S31 schedule and a source-linked operational condition with a reasoned human decision. Reopen it to verify persistence.
6. In Evidence→Sources, choose replacement for BASE, select `permit-B.docx` with the same BASE ID, and preview. Inspect impact before explicit commitment. Confirm affected checks/reviews require renewed attention while unchanged VARIATION evidence remains. Examine the earlier review/source in History. Reversing an earlier source must remain guarded.
7. In Exports & recovery, inspect the current version and outstanding work. Download JSON and Markdown evidence. Confirm they describe the same current/historical state and retain unresolved conditions. Refresh/reopen the production and confirm saved work remains.
8. Resize to a narrow window or use browser responsive mode at 390×844. Switch scenes using the native selector, use Next human action, open a review, Tab from reviewer through decision/rationale to the stage control, and inspect wrapping/focus. Return to the wide layout. Avoid leaving accidental staged work before switching production.

## Recovery within the same acceptance session

Encrypted recovery is owner-guarded and unavailable in evaluation. Use **Start-BeforeRoll-Private.cmd** and your existing local owner access for a new generated-only production, or use the isolated acceptance instance **http://127.0.0.1:3046/**. The acceptance harness is deliberately disconnected from `.env` and provider transport. If it is not running, execute `node _design_implementation/serve-acceptance.mjs` from the project folder; it serves 3045/3046 and preserves its generated stores. Do not run a second copy while those ports are already occupied.

For the isolated 3046 test instance only, its generated test token is defined in `serve-acceptance.mjs`; it is not your private owner credential. Open the recovered fictional Harbour case or create a fresh fictional production there. In Exports & recovery, download an encrypted backup using a test passphrase you retain. Open Recover a separate production. Select that backup and first try an incorrect passphrase: no restoration should occur. Verify with the correct passphrase, inspect inventory, type the exact production ID and restore separately. Confirm the picker labels the recovered copy, original production remains present, and its evidence/conditions/original custody agree. Open Storage and recovery health and wait for the actual result. Never use a Clocked retry as recovery.

## Acceptance record

Record one overall decision and any concrete defect: production ID/version, destination, exact interaction, expected outcome, observed outcome and screenshot. Judge the integrated application, including the secondary forms. The existing evidence and limitations are in reports 02–04; a test count alone is not the design-quality verdict.

Close only the launcher/harness window you started when finished. No deployment, GitHub push or hackathon submission is part of this acceptance.
